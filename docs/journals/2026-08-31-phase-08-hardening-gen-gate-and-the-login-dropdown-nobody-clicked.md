## The Brutal Truth

The infuriating part was the seed-session flake. A 5-worker concurrent JWT-timing collision under Playwright's default parallel load; the race was so tight it only showed up when all workers tried to verify OTP at once. The test would timeout randomly, the browser context would close early, and the error message pointed nowhere useful. Fixed with a bounded retry (2 attempts, 250ms exponential backoff), but the first extraction script that pulled the retry logic out of seed-session.ts grabbed the wrong block entirely — docblock and interface definitions instead of the actual function. Reconstructing from the intact source felt like untangling someone else's copy-paste accident, and the irritation stuck because the real problem (concurrent token verification timing) was fundamental to how Supabase auth works under load.

Also: the login language dropdown was invisibly broken for Phase 07. It rendered perfectly, was clickable, opened smoothly — but never actually switched the locale. Sat there doing nothing. The issue? Phase 07 wired locale-switching into the site header shell `(site)` layout, but the login page renders under `(auth)` layout and never received the `onSelectLocale` handler. No test caught it because the MoMorph test case only asserts "dropdown opens," not "content switches." The rebuild-spec W4 user-story inventory (wired vs. inert controls audit) surfaced it — caught by code reading, not test execution. That's the galling part: it took an automated audit of undocumented control-wiring to surface what a behavioral test should have caught.

## Root Cause Analysis

**Flake:** Concurrent Playwright workers all calling `verifyOtp` at once triggered a race in Supabase's token-generation and cookie-validation pipeline. JWT generation is async; each worker's token was issued at slightly different times. When the context tried to validate all five tokens simultaneously, Supabase's response ordering got inverted — some contexts received cookies for tokens that hadn't settled yet. The tight race window only shows under 5+ parallel workers; sequential or 2-worker runs never trigger it. This is a real production load signature, not test noise. Bounded retry with exponential backoff allows each worker's token to stabilize between attempts.

**Login dropdown:** Architectural scope creep, not a typo. Phase 07 implemented locale-switching as a shell concern, wiring it only into the `(site)` layout's header. The login page lives in the `(auth)` layout, which shares the same header component but was never wired to receive the `selectLocaleAction` server action. Component rendered (`LoginHeader` accepted optional props), dropdown opened, click handler existed — but the handler was `undefined` because the parent never passed it. No test caught it because the MoMorph TC row only requires the dropdown *opens*, not that it *works*. The test contract (UI presence, open/close behavior) was met; the business contract (interaction has an effect) was not.

## Lessons Learned

- **Render-only controls are invisible to smoke tests, and UI-presence assertions lie.** A clickable element that opens/closes passes every presence assertion even if the action is wired to null. Only an interaction test that asserts the *effect* (locale switches, content updates, navigation happens) catches it. An automated inventory of "what's wired vs. what renders inert" (the rebuild-spec W4 user-story/IPE audit) caught this because it reverse-engineered the code's actual control flow — what calls what, what gets passed where. Next time, build that inventory from the design before coding and cross-check it during code review.

- **Test case granularity mirrors the implementer's scope.** The MoMorph TC for the dropdown only required it *opens*; the shell-scoped implementation satisfied that exactly. A stronger assertion ("clicking EN changes the page language to EN") would have correctly failed the Phase 07 code under the login page's scope. The test bar was perfectly calibrated to the *shell's* concerns. The login page's own spec needed to say "locale switch works on `/login`" — that's a gap in the test case definition, not the implementation itself. This is a design problem (unclear scope boundaries between shared and page-specific concerns), not an implementation failure.

- **Flakes under concurrent load are a signal of real system bottlenecks, not test noise.** The 5-worker JWT-timing race happened because Supabase's token pipeline would actually jam under that load. Exponential backoff is the right fix for external-service timing collisions (not just a test-stabilization trick), and it's worth replicating in the real client code if high-concurrency auth is expected in production.

- **Rebuild-spec user-stories audit is an underrated defect-finding tool.** The W4 user-stories IPE (inventory of present elements, what's wired vs. inert) reverse-engineered the control flow from code and found an invisible broken feature. This is not a traditional test; it's a static audit of design-vs-code alignment. Worth building into the code-review checklist for shared/shell components that multiple pages consume.
